# AutoFlow AI

**Автоматизированный MLOps-пайплайн для работы с Big Data в условиях жестких инфраструктурных ограничений (OOM/RAM limits).**

## Бизнес-ценность и результаты (SMART)
Проект решает проблему обработки масштабных датасетов (на примере данных кредитного скоринга) на серверах с ограниченным объемом оперативной памяти без потери качества предиктивной аналитики.

* Оптимизация ресурсов (RAM): Снижена пиковая нагрузка на оперативную память в 6 раз (с 12 ГБ до 2 ГБ) за счет проектирования стратегии вертикального поколоночного пакетирования (Batching) и даункастинга типов данных[cite: 2].
* Качество моделей: Достигнута метрика ROC-AUC = 0.7607 (Macro-F1 = 0.8226)[cite: 2] при работе с дисбалансом классов с использованием автоматизированного подбора гиперпараметров через Optuna.
* Production-Ready метрики: Внедрена система инференса с бизнес-маршрутизацией (AUTO_ROUTE / REVIEW / HUMAN_REVIEW) и автоматический мониторинг Data & Concept Drift[cite: 2], генерирующий вердикты о необходимости переобучения.

## Стек технологий
* Core: Python, Pandas, NumPy, DuckDB (out-of-core processing)
* Machine Learning: Scikit-learn, LightGBM, Optuna
* MLOps & Pipeline: Custom Architecture (19-step automation), Drift Detection (Evidently/Custom)
* Deployment: Docker, Git

## Архитектура системы: Статус реализации

Проект разделен на 19 архитектурных шагов. Основное ML-ядро, пайплайны подготовки данных и базовая оценка дрифта (Шаги 1–16) полностью реализованы и протестированы. Текущий фокус разработки — замыкание эксплуатационного Production-контура (Шаги 17–19).

### Реализованный функционал (Steps 1–16)
* Steps 1–4: Автоматический EDA и контроль качества сырых данных (Quality Control).
* Steps 5–10: Подготовка данных, обработка пропусков и Feature Engineering pipeline.
* Steps 11–13: Формирование Canonical Dataset, расчет Baseline-модели и создание Reference Profile для будущего мониторинга.
* Step 14: Автоматическое улучшение модели градиентного бустинга.
* Step 15 (Inference & Routing): Скоринг новых данных с распределением потока на основе уверенности модели (Confidence):
  * AUTO_ROUTE — автоматическое принятие решения.
  * REVIEW — дополнительная проверка.
  * HUMAN_REVIEW — ручная модерация аномалий.
* Step 16 (Drift Monitoring): Детекция смещения данных. На выходе генерируется machine-readable вердикт (например: LOW -> NO_RETRAINING_REQUIRED).

### Инженерный Roadmap: Production-контур (Steps 17–19)

Следующие шаги формируют отказоустойчивую среду для реальной эксплуатации. Архитектура спроектирована так, чтобы система работала с реальными бизнес-файлами (например, daily_report.csv), где таргет-переменная может отсутствовать.

* Step 17: Automated Decision Orchestration (Мозг системы)
  Оркестратор, принимающий решение на основе артефактов Step 15/16. Соблюдает строгий инженерный принцип: модуль мониторинга дрифта не должен самовольно менять production-модель.
  * NO_RETRAINING_REQUIRED -> продолжение штатной работы.
  * REVIEW_RECOMMENDED -> автоматическое увеличение доли HUMAN_REVIEW, маркер MONITORING_REQUIRED.
  * RETRAINING_RECOMMENDED -> блокировка авто-обновления, формирование Retraining Request, постановка в очередь на обучение.
* Step 18: Persistent State & Recovery
  Обеспечение отказоустойчивости (Stateful-архитектура). При перезапуске сервиса или падении контейнера система не запускает обучение с нуля, а восстанавливает последнее состояние (state), загружает последнюю accepted model и продолжает обработку новых Job-ов.
* Step 19: Production Interface
  Единая точка входа для пакетного инференса. 
  Вход: Загрузка daily_report.csv -> Schema Validation -> Production Inference -> Routing -> Drift Monitoring -> Decision.
  Выходной лог:
  ```text
  Processed: 21 960 000 rows
  AUTO_ROUTE: 85% | REVIEW: 10% | HUMAN_REVIEW: 5%
  Drift: LOW
  Decision: NO_RETRAINING_REQUIRED
